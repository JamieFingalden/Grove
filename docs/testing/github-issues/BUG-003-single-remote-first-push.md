# 单远端且分支未设上游时，一键推送失败且没有可选择远端的菜单

- 类型：功能缺陷，S2（首次推送主流程受阻，有 CLI 绕过方式）
- 版本：Grove 3.0.0（9），macOS 27.0.1，Apple Silicon
- 复现：在同一个合成仓库重建“无上游”前置后，两次 GUI 定向复现；远端均为有效本地 bare 仓库

## 前置

1. 创建本地测试仓库，分支 main 含至少一个提交。
2. 创建本地 bare 仓库作为唯一远端 origin，已存在同 SHA 的 origin/main；本地 main 不配置 branch.main.remote 与 branch.main.merge。
3. 在 Grove 打开该工作树，刷新。界面显示“未设上游”，推送按钮 Help 为“推送并建立上游跟踪”。

测试不依赖账号、网络或真实托管平台。未设置自动建立上游的全局 Git 选项。

## 操作与实际结果

点击推送按钮，出现“推送失败”。最近错误：

> The current branch main has no upstream branch.

Grove 同时提示“请从推送按钮的菜单选择目标远端，首次推送会自动建立关联”。但只有一个远端时界面渲染的是普通按钮，没有远端选择下拉菜单。两次失败后上游仍为空，HEAD 与 bare 远端分支 SHA 均未变化。

## 预期

唯一远端明确且分支未设上游时，按钮能推送当前分支并建立上游；若不自动选择，则提供实际可操作的远端选择入口，且提示与界面一致。

## 对照与影响

仅在合成仓库中通过 CLI 将 main 关联到 origin/main 后，GUI 的同一按钮立即“推送完成”。移除该合成上游配置、刷新后，再次点击又失败。说明本地 bare 远端有效，失败由无上游路径触发。

原生 Git 诊断对照：不显式传远端/分支的 git push --dry-run --set-upstream 也返回同样错误，并建议显式使用 git push --set-upstream origin main。

源码辅助定位：WorktreeDetailView.swift 的 pushControl 只有远端数大于一时渲染菜单并传入目标；单远端按钮调用 model.push()。GitClient.push 在目标为 nil 时不追加远端名与分支名。源码用于解释真实复现，不替代测试结果。

## 修复验收

1. 一个远端、当前分支无上游、存在同名远端分支时，GUI 推送成功且正确设置上游。
2. 同样覆盖远端尚无该分支的首次发布；不能要求用户先修改全局 Git 配置。
3. 已有上游与多个远端的推送行为正常，不改变原跟踪目标。
4. 错误提示不再引导用户寻找界面没有提供的菜单。

完整本地证据索引见 docs/testing/ISSUES.md 的 BUG-003；包含前后 Git 配置、两次 GUI 失败、有效远端 SHA 与成功对照。
