## 问题

仓库已配置有效的 `origin`，但 Grove 的「评审请求」项目页仍显示“这个仓库没有配置远端。”，将“未识别为支持的平台”误报成“没有 Git 远端”。工作树页能够看到该远端，并在推送按钮帮助中说明无法识别其地址。

## 环境与复现数据

- Grove 3.0.0（9），macOS 27.0.1，arm64。
- 使用本地合成 Git 仓库，`origin` 指向有效的本地 bare remote，不涉及真实平台账户或远端。

## 复现步骤

1. 在 Grove 打开已配置有效 `origin`、但该地址不是受支持托管平台地址的本地仓库。
2. 查看工作树页的推送按钮帮助，确认界面提示无法识别 `origin` 地址。
3. 打开「评审请求」项目页，查看空状态文案。
4. 点击 Grove 工具栏「刷新」，再切回工作树页并返回项目页，重复查看。

## 预期结果

项目页应区分“没有配置远端”和“已配置远端，但无法识别或不支持其托管平台”。后者应清楚说明平台集成不可用，同时保留 Git 远端已配置这一事实。

## 实际结果

项目页显示“还没接入这个平台 / 这个仓库没有配置远端。”工作树页同一仓库的推送按钮帮助则显示“无法识别 origin 的地址”。工具栏刷新以及重新进入项目页后，文案仍一致。只读 `git remote -v` 确认 `origin` 的 fetch 和 push 地址均配置到有效的本地 bare remote。

## 影响与严重程度

S3。工作树和 Git 操作仍可用，但项目页给出的事实不准确，可能使用户误以为必须重复添加远端或修复 Git 配置。

- `dist/qa/20261020/deep/codex-20261021/platform-local-origin-project-ax.txt`、`platform-local-origin-project-repro2-ax.txt`：两轮项目页刷新后的 AX 文案。

对外问题描述仅涉及通用本地合成仓库；本机界面截图不随 Issue 上传。

## 修复验收

使用配置了有效 `origin`、但地址不属于受支持平台的仓库，项目页应显示“已配置远端但平台未识别/不受支持”一类准确提示；在没有任何远端时才显示“没有配置远端”。刷新和重新进入页面后，两种状态仍应正确区分。
