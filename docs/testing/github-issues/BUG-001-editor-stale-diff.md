# 缺陷：内置编辑器保存并完成后，diff 不自动刷新，仍显示旧内容

- 类型：功能缺陷（确认，已两次独立复现）
- 严重程度建议：S3（次要功能问题，不丢数据，但显示内容有误导性）
- 复现次数：2（两名独立测试执行者分别复现，现象一致）
- 测试版本：3.0.0（build 9）
- 测试环境：macOS 27.0.1（26A434），Apple silicon（arm64）
- 测试数据：本地合成 Git 仓库（目录名含中文与空格，含已暂存/未暂存/未跟踪三类改动），全程只操作合成仓库

## 前置条件

1. 一个本地 Git 仓库，工作区中有一个未暂存的文本文件 `src/main.txt`（基线 2 行，工作区含未暂存修改）。
2. 在 Grove 中打开该仓库，进入「变更」页，选中该文件的 diff 视图，此时 diff 显示与 `git diff` 一致。

## 复现步骤

1. 选中未暂存文件 `src/main.txt`，点 diff 区的「编辑」按钮，打开内置编辑器面板。
2. 在编辑器末尾追加一行新文本（例如「分行测试丙：编辑器复现」）。
   面板出现「有未保存的修改」横幅，行数/字符计数更新，「保存」按钮变为可用。
3. 点「保存」：横幅消失，「保存」回到禁用状态（写入成功）。
4. 点「完成」关闭编辑器，不点「刷新」，立即观察该文件的 diff 区。

## 预期结果

保存成功后（最迟在关闭编辑器时），该文件的工作区 diff 应自动重算，与 `git diff` 输出一致（hunk 头与行内容），无需用户手动刷新。

## 实际结果

- 关闭编辑器后 diff 区仍显示旧内容：hunk 头保持保存前的 `@@ -1,3 +1,5 @@`，行内容不含新追加的行。
- 同一时刻 CLI 核对：磁盘文件已含新行；`git diff` 真实 hunk 头为 `@@ -1,3 +1,6 @@`。界面显示与仓库实态不一致。
- 点工具栏「刷新」后，diff 立即更新为 `@@ -1,3 +1,6 @@` 并出现新增行，证明数据写入成功、仅视图未刷新。

## 影响

用户编辑保存后看到的 diff 是过期的，可能基于旧内容做暂存/提交决策：例如以为追加失败而重复编辑，或按旧 diff 勾选行级暂存。

## 修复验收条件

1. 编辑器保存成功返回后，该文件的工作区 diff 自动更新，与 `git diff` 的 hunk 头和行内容一致。
2. 全程不依赖用户手动刷新。
3. 回归步骤同上：追加一行 → 保存 → 完成 → 立即读 diff，无需刷新即含新增行。

## 证据（本地验收记录，文件名）

- `glm-editor-repro.md`（第二次独立复现全过程）
- `glm-editor-repro-verify.txt`（CLI 同刻基线与编辑后核对）
- `glm-editor-repro-1-stale-diff.png`（刷新前：旧 hunk，无新增行）
- `glm-editor-repro-2-after-refresh.png`（刷新后：hunk 头 +1,6 与新增行）
- `ui-07-editor-stale-diff-before-refresh.txt` / `ui-08-editor-diff-after-refresh.txt`（第一次复现，另一执行者，AX 抓取：刷新前 `@@ -1,2 +1,3 @@` 缺两行，刷新后 `@@ -1,2 +1,5 @@` 出现）
