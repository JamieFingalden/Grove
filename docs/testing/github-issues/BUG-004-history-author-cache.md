## 问题

历史页工具栏「刷新」可以读取外部新提交并显示在提交图中，但作者筛选菜单仍使用旧的作者列表和计数。用户无法在刷新后立即按新作者筛选；正常退出并重新打开 Grove 后，新作者才出现在菜单中。

## 环境与数据

- Grove 3.0.0（9），macOS 27.0.1，arm64。
- 使用本地合成测试仓库和合成作者数据。
- 第二次复现的外部提交：`066b0555240dd8fa3aab80e55c5f05a1f0d63514`，作者 `测试丙 <filter-c@test.local>`，提交说明「作者缓存复现丙」。

## 复现步骤

1. 在历史页打开一个提交作者菜单已有数据的仓库。
2. 在 Grove 外部用 Git CLI 创建一条由此前菜单中不存在的作者提交的新提交。
3. 回到 Grove，点击工具栏「刷新」。
4. 检查提交图和作者筛选菜单。

## 预期结果

刷新后，作者筛选菜单应同步显示新作者及正确的提交数；选择该作者后，历史列表应筛出该作者的提交。无需退出并重启应用。

## 实际结果

两次复现中，点击工具栏刷新后提交图都已显示外部新提交，作者菜单却仍只显示刷新前的作者及计数。第一次新增作者甲的两条提交和作者乙的一条提交后，菜单仍只列原作者「测试者」2 条；退出并重新打开 Grove 后，甲、乙才出现。第二次重启后，菜单列出甲 2 条、测试者 2 条、乙 1 条；再由测试丙创建 `066b055` 后，刷新使提交图出现「作者缓存复现丙」，但作者菜单仍没有测试丙。CLI `git shortlog -sne HEAD` 确认仓库共有四位作者、六条提交。

## 证据

- `h2-authors-after-manual-refresh.png`：第一次刷新后，图中已有新提交，展开的作者菜单仍只有原作者及 2 条计数。
- `h2-author-c-visible-in-history.png`：第二次刷新后，提交图显示 `066b055`「作者缓存复现丙」。
- `h2-author-c-missing-menu.png`：同一轮作者菜单只列甲、测试者和乙，没有测试丙。
- `h2-new-author-c-commits-ax.txt`：AX 同时记录 `066b055` 出现在历史列表及作者菜单入口。
- `parent-oracles.txt`：提交完整 SHA、作者及邮箱、作者提交数和仓库总提交数的 CLI 判据。

以上证据均来自专用合成仓库，不包含用户真实项目数据。

## 严重程度与验收

严重程度：S3。该问题不改变 Git 历史，但使历史页筛选项在刷新后过期，且目前需要重启应用才能恢复。

验收条件：在历史页打开期间，从外部新增不同作者的提交并点击工具栏刷新；作者菜单应立即更新作者及计数，选择该作者能正确筛出新提交，整个流程不需要重启 Grove。
