# Grove 3.0.0 真实软件验收测试计划

- 被测对象：Grove 3.0.0（build 9），打包产物 `dist/Grove.app` 与 `dist/Grove-3.0.0.dmg`
- 基线提交：`8212f60405fd3f0d616c21b35e276ba9f52275ed`
- 测试环境：macOS 27.0.1（26A434），arm64
- 测试日期：2026-10-20
- 证据根目录：`/Users/jamie/Documents/code/tools/Grove/dist/qa/20261020/`

## 1. 目标

对真实打包产物执行标准软件验收测试：验证安装启动、仓库管理、变更与 diff、暂存与提交、
分行暂存、工作树管理、历史筛选、标签、重启恢复、无托管平台提示、Daily / Workspace 等
本地功能在真实 macOS 图形界面下的行为，并以 Git / 文件系统的客观状态作为判据。
外部依赖（PR/MR、真实 SSH、AI、真实平台推送）在前提未评估前一律记「未执行」，不以 mock 冒充通过。

## 2. 角色与分工

GUI 操作不限于特定人员：**任何具备真实电脑控制能力（computer-use）的执行者均可操作界面**，
包括 Claude Code、pi、ZCode 等代理或人工测试者；不同执行者可以分批接力执行同一清单。
没有电脑控制能力的执行者只做 CLI 造数、判据核对与证据审阅，**不得假装执行了 GUI**。

| 角色 | 职责 |
| --- | --- |
| GUI 执行者（需 computer-use） | 打开安装包、按用例清单操作真实界面、保存 AX 文本与截图 |
| CLI 执行者（无需 computer-use） | 造数、`--doctor` 诊断、判据命令核对、归档日志、审阅证据、出具报告与登记 Issue |

署名规则：所有产物必须注明产生方式——「<执行者> CLI 执行」「<执行者> GUI 实测（computer-use）」
「<执行者> 证据审阅」。同一用例由多个执行者接力时，分别署名，不得混称。

## 3. 范围

### 本轮在测（GUI，由具备电脑控制能力的执行者执行）

1. 安装与首次启动（DMG 拖装、签名验证、首启窗口）
2. 打开仓库 / 重复打开同一仓库 / 打开非仓库目录的错误提示
3. 变更列表与 diff（未暂存、已暂存、未跟踪、重命名、二进制）
4. 暂存、取消暂存、提交
5. 分行暂存（hunk / 行级勾选）
6. 工作树创建、锁定、解锁、脏工作树删除保护
7. 历史字面量筛选（`foo(bar)` 按字面量而非正则）
8. 标签创建（附注 / 轻量，本地操作）
9. 重启恢复（页面与启动偏好、仓库列表持久化）
10. 无托管平台提示（本地 origin 时的评审不可用文案）
11. Daily 页（本地今日提交与作者筛选）、Workspace 页（无平台时的空态/提示）

### 未执行项（不在本轮判定通过）

- PR / MR 浏览与操作（依赖真实 GitHub / GitLab 平台）
- 真实 SSH 远程仓库管理
- AI 生成（提交信息、标签说明、AI Review）
- 推送到真实托管平台（含标签推送）
- 公证与 Gatekeeper 远程验证（本机 Apple Development 签名，未公证）

以上项的前提未逐一评估前一律记「未执行」，不擅自标「阻塞」；只记录环境事实（CLI 是否存在、
是否登录），不执行、不 mock、不计通过。

## 4. 测试流程（可重复标准链：构建 → 校验 → 独立造数 → 真实 GUI → Git 判据 → 缺陷复现 → Issues → 报告/验收）

1. **构建或复用**：首次打包执行 `zsh scripts/build.sh` 与 `zsh scripts/make-dmg.sh`，退出 0，日志留档；
   对同一固定包的接力/专项轮次复用原产物，记录 SHA256，不重复构建。
2. **校验**：`plutil -lint`、`lipo -archs`、`codesign --verify --deep --strict`、`shasum`，
   新构建按需跑一次 `swift test` 作为回归基线，同包接力引用已有基线；结果记入 `evidence/package-checks.md`。
3. **独立造数**：运行 `scripts/qa-local.sh`（详见 RUNBOOK），在工程与任何仓库之外的独立测试根
   （默认 `/private/tmp` 下时间戳目录）生成合成 Git 仓库（中文与空格路径、不同提交人、
   含 `foo(bar)` 的历史、两段相隔修改、未跟踪文件、重命名、二进制文件、本地 bare origin 与备用远端、
   非仓库目录）。脚本拒绝覆盖已有目录；测试身份用仓库本地配置 / `git -c`，不改全局配置。
   每轮使用独立的 `--test-root` / `--artifacts`，不清理、不覆盖旧证据。
   CLI 造数与 doctor 只用于数据准备与链路诊断，不作为 GUI 通过的依据。
4. **真实 GUI**：具备电脑控制能力的执行者按 TEST_CASES 顺序操作真实界面；没有电脑控制能力
   不得假装执行 GUI。每条用例保存 AX 文本与截图到本轮 artifacts 的 `evidence/`，文件名用
   `<执行者前缀>-<用例ID>-<现象>` 约定，便于按执行者分别署名。
5. **Git 判据**：对每条 GUI 结果运行 RUNBOOK 的 Git / 文件系统核对命令，界面表现与仓库实态
   一致方判 PASS。
6. **缺陷复现**：核对真实输入与界面、Git/文件判据，在重建的合成前置上定向复现一次；
   可由同一执行者完成，条件允许时交叉复核。高风险数据损坏证据充分即登记；
   复现失败且证据不足的现象单列待核实。只记录实际观察到的后果，不将暂存等同于提交。
7. **Issues**：确认缺陷先查重（`gh issue list --state all`），再用 `gh issue create` 登记，
   正文文件存档在 `docs/testing/github-issues/`，返回 URL 回填 ISSUES.md；不得预写未创建的 URL。
8. **报告/验收**：出具 `docs/testing/TEST_REPORT_<日期>.md` 结果矩阵，逐条对齐 TEST_CASES 的 ID
   并列补充用例；重新计算合计，不引用任何执行者自述的未核对计数。缺陷修复验收以 Issue 中的
   验收条件为准；确认前不修改产品源码。

## 5. 判据与缺陷分级

- **PASS**：UI 操作后预期行为可见（AX 文本/截图），且 Git / 文件系统判据命令输出一致。
- **FAIL**：预期行为未出现、出现非预期错误，或 Git 实态与界面不符。负例正确报错且无副作用属于 PASS。
- **未执行**：前提未满足或未评估（缺登录、缺平台、缺网络授权等），记录事实后挂起，不擅自归为阻塞。
- 缺陷分级：S1 崩溃/数据丢失；S2 主流程不可用；S3 次要功能或文案问题；S4 建议项。

## 6. 证据管理

```
dist/qa/<日期>/
├── evidence/              # AX 文本 .txt + 截图 .png + CLI 判据（GUI 执行者与 CLI 执行者分别署名）
├── installed/Grove.app    # 实际运行的安装副本
├── logs/                  # doctor 日志、退出码（CLI 执行者产生，随 artifacts 独立成轮）
└── summary.txt            # 脚本机器事实汇总（独立测试根轮次在各自 artifacts 下）
```

最终报告固定放在 `docs/testing/TEST_REPORT_<日期>.md`，问题详单在 `docs/testing/ISSUES.md`。

文件一律 UTF-8 无 BOM；报告不包含凭据、密钥或用户私有仓库源码正文。

## 7. 开始、收尾与修复回归

- 开始条件：版本、构建号、包校验值与实际运行路径对应；为本轮分配专用测试根；
  正例/负例前置都能通过 CLI 确认；界面操作只由一名执行者控制，交接前先停止上一执行者。
- 每项先记录前置和预期，再执行界面动作，立即落盘判据。涉及破坏性动作的测试先验证取消，
  只对明确可丢弃的合成数据确认。输入值需经过截图或真实键盘操作验证，不能只相信自动化 setValue 返回成功。
- 收尾条件：计划中每项都有最终状态、执行者与证据或明确的未测原因；确认问题已查重登记并有本地详单；
  报告统计可从矩阵重算；编码检查通过。达到收尾条件表示测试工作交付，不等于产品没有缺陷或准予发布。
- 数据丢失、错误仓库写入、崩溃及核心流程不可用优先报告。未解决的高风险问题、隔离受限项和外部服务未测项
  必须在结论中明确，不用「大部分通过」掩盖剩余风险；发现缺陷数量不作为测试达标指标。
- 用户要求修复后，以原缺陷步骤和同一数据判据验收，再补一个受影响的相邻场景；
  只有代码变化或新失败说明有必要时才扩大回归，不机械重复整轮或全量单测。
